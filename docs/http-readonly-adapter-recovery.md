# 独立 HTTP/MCP 接口接手记录

独立后端现在有一个可选的本机适配器 `packages/alpha-engine/http-server.cjs`。它把已经通过 protobuf/Go bridge 验证的 DTO 查询和受控会话文件导出暴露为本机 HTTP 接口，并提供一组明确列出的 MCP 工具。它不复用原包的 `HttpApiService`、原网关、原 MCP 命令，也不改变原包的完整性策略。

启动独立引擎时设置一个 32–256 位可见 ASCII 令牌即可启用适配器：

```sh
ALPHA_INDEPENDENT_HTTP_TOKEN="$(openssl rand -hex 32)" \
ALPHA_INDEPENDENT_HTTP_PORT=5031 \
npm run start:independent
```

`scripts/environment.mjs` 会在独立模式下校验并保留这两个变量，`recovery-runtime.cjs` 再将它们传给 Electron 启动的独立 engine；原包模式会丢弃这组变量。这样从桌面启动器运行时，监听器配置与直接运行 engine 的行为一致。

适配器只监听 `127.0.0.1`，拒绝 `Origin`、非本机 Host、缺失或不匹配令牌，以及超过 1 MiB 的请求体。健康检查 `/health` 和 `/api/v1/health` 不需要令牌。支持的 HTTP 路径是账号、会话、消息、搜索、联系人、通讯录目录、群成员、候选记录（含独立消息派生候选入口）、独立消息来源文本、显式数据源 revision/watcher 诊断、合成语音 WAV 解析、合成朋友圈时间线/作者、合成收藏列表及合成收藏媒体槽位/解析、聚合分析任务、导出能力/统计、导出格式、受控会话导出和媒体元数据导出，分别映射到已验证的独立 protobuf 方法；目录路径只允许 `friend` 和 `group` 两种已有证据支持的分类。显式数据源诊断另提供 `GET /api/v1/independent/source/revision` 与 `GET /api/v1/independent/source/watch-targets`；它们只调用独立引擎既有的账号/source 选择和路径权限校验，响应固定带 `scope=alpha-independent-source-diagnostics`、`complete=false`、`native_schema_supported=false`，不扫描用户目录或修改数据。独立定时导出另提供 `/api/v1/independent/export-schedules`（GET 列表、POST 创建/替换）、`/api/v1/independent/export-schedules/:schedule_id`（GET、DELETE，或 POST `action=run-now`）、`/api/v1/independent/export-schedules/:schedule_id/runs` 与 `/attempts` 列表、根级运行/尝试列表、单条运行/尝试查询及 `/api/v1/independent/export-attempts/:attempt_id/retry`；这些路径只包装本地 stateDir 的 CAS、bounded scheduler、运行/尝试记录和重试状态，响应固定带 `scope=alpha-independent-scheduled-export`、`complete=false`、`native_schema_supported=false`，不别名官方计划 API。`GET /api/v1/export-capabilities` 返回独立后端已验证的格式、媒体和时间范围能力；`GET /api/v1/export-stats?conversation_ids=a,b` 返回最多 100 个指定会话的消息总数、类别计数及首末时间。二者只描述独立 DTO，不冒充官方/native formatter 兼容。`GET /api/v1/sns/timeline`、`GET /api/v1/sns/usernames` 和 `GET /api/v1/sns/day-counts` 只读取显式 `moments.db`/`__alpha_moments_v1` synthetic fixture，响应标记 `synthetic_only=true`、`native_schema_supported=false` 并保留 `source_database`/`source_table`；日计数使用半开日期区间，最多 366 天，UTC 偏移限制为 -840 到 840 分钟；它们不读取或猜测真实微信 `SnsTimeLine`/`snsmessage`。朋友圈导出使用独立命名空间：`POST /api/v1/independent/moments/exports` 启动 metadata-only 任务，`GET /api/v1/independent/moments/exports/:job_id` 查询，`POST /api/v1/independent/moments/exports/:job_id/cancel` 取消。它们只消费 `moments.db`/`__alpha_moments_v1` synthetic fixture，响应带 `synthetic_only=true`、`native_schema_supported=false`，支持 `json`、`markdown`、`html`、`txt`；图片、视频和 live photo 请求明确返回 `HTTP_API_MOMENTS_MEDIA_UNAVAILABLE`。这些自有路径不实现或别名官方 `/api/v1/sns/export`，也不声称真实朋友圈媒体、点赞、评论或原生 formatter 语义。`GET /api/v1/favorites` 只读取显式 `favorite.db` 或 `favorites.db` 中的 `__alpha_favorites_v1` synthetic fixture，提供有界分页、类型/关键字/标签过滤和类型计数，并标记 `synthetic_only=true`、`native_schema_supported=false`；真实收藏库 schema、source lookup 和原生媒体 token 仍不可用；`GET /api/v1/favorites/:favorite_id/media` 读取可选 `__alpha_favorite_media_v1` 槽位，`GET /api/v1/favorites/media/:token` 解析自有 `fav1_<32 hex>` token；`include_media=true` 仍返回 `FAVORITES_MEDIA_UNAVAILABLE`。`GET /api/v1/records` 仅接受 `payments`、`friend_requests`、`revokes`、`calls`，支持不超过 512 字节、无控制字符和首尾空白的字面 `query`，以及 `ascending=true|false` 的分页，并在响应中保留 `partial=true`、`candidate=true` 和来源字段；朋友圈互动和搜索历史仍返回明确错误。独立扩展 `GET /api/v1/independent/records` 使用同一查询边界，但额外返回 `scope=alpha-independent-message-derived-candidates` 和 `native_schema_supported=false`。`GET /api/v1/independent/message-source` 要求账号、会话、消息 ID 和独立 `independent1_...` canonical base64url source token，只返回重新定位后确认的 UTF-8 解码文本，响应标记 `scope=verified-message-text`、`complete=false`、`native_schema_supported=false`、`raw_available=false` 和 `media_ready=false`；它不接受原生 `media1_...` token，不读取原始 XML、媒体文件或数据库密钥。
`GET /api/v1/independent/media/voice-playback` 只接受账号和 64 位小写十六进制 `media_id`，转发已验证的 `decodeVoicePlayback` 并返回 `wav_media_id`；响应标记 `synthetic_only=true`、`native_schema_supported=false`、`schema=__alpha_voice_playback_v1` 和 `scope=synthetic-voice-playback`。该路由不返回音频字节，不解析真实 VoiceInfo/SILK，也不接受原生媒体 token。`POST /api/v1/analysis` 只接受已验证的聚合 scope 1–4 及其有界时间/会话参数，`GET /api/v1/analysis/:analysis_id` 读取任务状态，`POST /api/v1/analysis/:analysis_id/cancel` 取消运行中的任务；报告限 64 MiB，完成时作为独立 JSON 返回。

`POST /mcp` 实现 Streamable HTTP 的 `initialize`、`ping`、`tools/list` 和 `tools/call`，目前声明并处理 58 个工具：状态与账号信息、联系人列表/目录/解析/profile、群成员、会话列表与解析、会话消息、搜索发送人、消息搜索、消息原始 DTO、独立消息命中定位（`alpha-independent.messages.resolve_search_hit`）、独立消息来源文本（`alpha-independent.messages.get_source`，只接受独立 source token 并返回已解码文本）、显式 v4 媒体元数据探针（`alpha-independent.media.probe`，只读取 hardlink.db/media_*.db 的元数据并标记 metadata-only）、合成语音播放解析（`alpha-independent.media.decode_voice_playback`，只接受 synthetic marker 映射和自有 WAV media-index）、消息前后文、首条/日期锚点、每日计数、独立年度基础统计和会话关系基础统计（`alpha-independent.analytics.analyze_annual`、`alpha-independent.analytics.analyze_conversation`）、会话/账号媒体元数据浏览（`alpha-independent.media.browse_conversation`、`alpha-independent.media.browse_account`，只返回 refs/display/source identity 并标记 `media_ready=false`）、合成朋友圈时间线/作者/日计数、合成朋友圈 metadata-only 导出任务（`alpha-independent.moments.start_export`、`alpha-independent.moments.watch_export`、`alpha-independent.moments.cancel_export`）、合成收藏列表（`alpha-independent.favorites.list_items`）、合成收藏媒体槽位/解析（`alpha-independent.favorites.list_media_slots`、`alpha-independent.favorites.resolve_media`）、独立导出能力/统计、scope 1–4 聚合分析任务、九种会话文件导出、媒体 JSON/CSV 元数据、独立搜索页、独立移动端账号/会话概览（`alpha-independent.mobile.get_overview`）、独立数据源诊断工具（`alpha-independent.source.get_revision`、`alpha-independent.source.get_watch_targets`，只返回显式源的稳定 revision 和 watcher 目录，标记 `scope=alpha-independent-source-diagnostics`、`complete=false`、`native_schema_supported=false`），独立定时导出计划/运行/尝试工具（`alpha-independent.schedules.list`、`get`、`save`、`delete`、`run_now`、`list_runs`、`get_run`、`list_attempts`、`get_attempt`、`retry_attempt`）以及 `wechat.forensics.list_records` 和独立 `alpha-independent.records.list_candidates`。后者返回 `scope=alpha-independent-message-derived-candidates`、`partial=true`、`candidate=true` 和 `native_schema_supported=false`，不兼容原生 Alpha 记录库 schema。独立移动端概览仅组合 `listAccounts` 与分页 `listConversations` 的已验证 DTO，返回 `scope=alpha-independent-verified-dto`、`coverage=verified-account-and-session-dto`、`complete=false`、`native_schema_supported=false`，不加入官方移动端快照未验证的未读数、静音状态、头像、移动端缓存、媒体链接或原生 schema。独立消息命中定位要求会话 `conversation_id`/`username` 和十进制 `server_id`，只复用已验证 `locateMessage` 的消息 DTO 与前后游标，返回 `exact_identity`，同时标记 `native_schema_supported=false`，不实现或别名官方 `alpha.messages.resolve_search_hit`。两个独立 analytics 工具同样返回结构化报告并标记 `complete=false`、`native_schema_supported=false`；年度工具只覆盖可发现会话，关系工具只覆盖指定会话的已验证消息，报告中的 NLP、朋友圈和回复语义保持空或 null，不复用官方 `wechat.analytics.*` 名称。`wechat.core.list_tools` 按官方名称提供当前适配器的只读工具目录，可用完整 package 前缀（如 `wechat.chat`、`alpha`）过滤；返回 `complete=false`、`scope=alpha-independent-readonly-adapter` 和 `native_schema_supported=false`，明确不代表原 Alpha/native 的完整目录。该目录排除本地文件导出工具和三个 moments 导出任务；`tools/list` 仍保留它们的独立适配器声明。朋友圈导出工具只写 metadata-only synthetic 文件，不实现官方 `wechat.moments.*` 工具或 `/api/v1/sns/export` 语义。导出统计工具要求调用方显式提供 1–100 个会话 ID，返回独立 DTO 的总数、类别计数和首末时间；不扫描未选会话，也不宣称原 ChatLab 统计语义。聚合分析报告来自已验证消息/session DTO，使用独立 `alpha-aggregate-v1`、`alpha-annual-v2` 或 `alpha-dual-v1` JSON 外壳，不包含 NLP 或原生 Alpha 报告兼容承诺。后者只读取引擎已经从消息 XML 证明的 `payments`、`friend_requests`、`revokes`、`calls` 四类虚拟表，支持不超过 512 字节的有界字面查询和升降序分页，并在结果中保留 `partial`/`candidate` 标记、原始 `fields` 和来源字段；不把候选记录解释为完整业务记录。消息原始工具只返回已验证 DTO 字段（含来源标识、长整数、显示 JSON 的 Base64 和独立 source token），不返回数据库密钥、原始 XML 或本地媒体路径。联系人 profile 只返回独立引擎能证明的存在性、共同群和群成员字段；通讯录目录只派生已验证的好友和群聊。工具参数对象和字段均做白名单校验，游标扫描最多 128 页/10,000 条；未知工具以 MCP `isError` 返回。没有发送消息、写入数据库、真实朋友圈 schema/互动/媒体下载、真实收藏库/原生收藏媒体语义或任意 SQL 工具；朋友圈和收藏 HTTP/MCP 工具只面向上述各自 synthetic fixture。

新增的上下文工具只使用独立引擎已经验证的消息 DTO：`get_message_around` 接受消息 `id`、`serverId` 或 `localId`，`get_message_anchor` 支持首条消息和 `YYYY-MM-DD` 日期，`get_daily_message_counts` 使用独立引擎的会话日计数。它们不会返回原始 XML、本地媒体路径、数据库密钥或未经验证的原 Alpha 媒体 token。

`POST /api/v1/exports` 只允许独立引擎已验证的 `json`、`markdown`、`html`、`txt`、`xlsx`，以及由已验证消息 DTO 生成的派生 `chatlab-json`、`chatlab-jsonl`、`sql`、`weclone` 格式；派生格式不声称与原 Alpha/native formatter 或第三方工具完全兼容。`POST /api/v1/media-metadata` 只允许 `media-json`、`media-csv`，可省略会话标识以导出账号范围，接收绝对 `destination_path` 和可选的毫秒时间范围；引擎会拒绝源目录/状态目录、符号链接、已有目标、媒体打包和未支持格式，不覆盖已有文件。该接口写入一个新导出文件，因此不把文件写入称作数据源只读操作。

这是一层独立适配器，尚未声称兼容官方文档中的全部 24 个 HTTP 路径和 60 个 MCP 工具。官方接口中依赖原生媒体、朋友圈、收藏、发送和完整 ChatLab 语义的路径仍需逐项取得 schema 和运行证据后实现。当前测试使用合成引擎 DTO，验证令牌、Host/Origin、HTTP 路由、游标/长整数转换、受控导出、MCP 工具、参数白名单和未知工具错误；没有读取真实微信目录。

可用 `npm run audit:api` 重新生成覆盖报告（也可直接运行 `node scripts/audit-api-coverage.mjs --check`）。报告只统计官方路径和工具是否在独立适配器中有显式入口，不把合成 DTO、静态路由或协议声明当作真实 native 兼容证据；当前缺失项会作为审计结果保留，不能用空成功响应掩盖。

媒体元数据导出只写入消息 DTO 中已经验证的来源库/表/行号、时间、发送者、refs 和 display 字段，并固定写入 `metadataOnly=true`、`mediaReady=false`。它不读取、解密、下载、播放本地媒体，也不生成 Alpha 原生 `media1_` token。
