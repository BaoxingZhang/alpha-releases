# 独立 HTTP/MCP 接口接手记录

独立后端现在有一个可选的本机适配器 `packages/alpha-engine/http-server.cjs`。增量读取另提供自有路径 `GET /api/v1/independent/sessions/:conversation_id/messages` 与 MCP 工具 `alpha-independent.chat.get_incremental_messages`。它只复用已验证的 `listMessages` DTO，接受 `since_unix_ms`/`end_unix_ms`（也可用 `since`/`end`）的排他毫秒边界、最多 500 条的 `limit`、opaque `cursor` 和 `ascending`，返回 `alpha-independent-chatlab-incremental.v1`。另有 `GET /api/v1/independent/sessions/:conversation_id/history` 与 MCP `alpha-independent.chat.resolve_history`，按最多 32 页读取同一已验证 DTO，固定 `coverage=verified-message-dto`、`partial=true`、`complete=false`、`native_schema_supported=false`、`raw_available=false`、`media_ready=false`，不兼容官方 ChatLab history/nextSince 语义；它返回 `alpha-independent-chat-history.v1`，`compatibility=alpha-independent-message-v1`，并固定 `chatlab_compatible=false`、`complete=false`、`native_schema_supported=false`。该入口是独立组合适配器，不实现官方 ChatLab 增量同步的 `nextSince`、历史水位、冲突解决或官方 schema 兼容语义。它把已经通过 protobuf/Go bridge 验证的 DTO 查询和受控会话文件导出暴露为本机 HTTP 接口，并提供一组明确列出的 MCP 工具。它不复用原包的 `HttpApiService`、原网关、原 MCP 命令，也不改变原包的完整性策略。

启动独立引擎时设置一个 32–256 位可见 ASCII 令牌即可启用适配器：

```sh
ALPHA_INDEPENDENT_HTTP_TOKEN="$(openssl rand -hex 32)" \
ALPHA_INDEPENDENT_HTTP_PORT=5031 \
npm run start:independent
```

`scripts/environment.mjs` 会在独立模式下校验并保留这两个变量，`recovery-runtime.cjs` 再将它们传给 Electron 启动的独立 engine；原包模式会丢弃这组变量。这样从桌面启动器运行时，监听器配置与直接运行 engine 的行为一致。

适配器只监听 `127.0.0.1`，拒绝 `Origin`、非本机 Host、缺失或不匹配令牌，以及超过 1 MiB 的请求体。健康检查 `/health` 和 `/api/v1/health` 不需要令牌。 `GET /api/v1/security/lock-status` 与 MCP `wechat.core.get_lock_status` 只返回独立密码锁的非敏感状态；密码、失败计数、重试时间、解锁和配置操作均不通过适配器暴露。 `GET /api/v1/independent/components/status?component=1|2|3|5|6` 与 MCP `alpha-independent.components.get_status` 只返回已有引擎静态高级组件诊断（`availability=1`、`INDEPENDENT_ADVANCED_COMPONENT_UNSUPPORTED`）；响应固定 `complete=false`、`native_schema_supported=false`，不做动态授权、设备密钥、下载或 native 启动，也不增加原生支持矩阵。支持的 HTTP 路径是账号、会话、消息、搜索、联系人、通讯录目录、群成员、显式 synthetic 群置顶、候选记录（含独立消息派生候选入口）、独立消息来源文本、显式数据源 revision/watcher/schema 诊断、合成语音 WAV 解析、合成朋友圈时间线/作者、合成收藏列表及合成收藏媒体槽位/解析、聚合分析任务、导出能力/统计、导出格式、受控会话导出和媒体元数据导出，分别映射到已验证的独立 protobuf 方法；目录路径只允许 `friend` 和 `group` 两种已有证据支持的分类。`GET /api/v1/independent/group-pins?chatroom_id=...` 只读取显式 `__alpha_group_pins_v1` fixture，并返回固定的 seq/sender_id/server_id/local_type/preview/pinned_by 字段；响应标记 `synthetic_only=true`、`native_schema_supported=false`、`complete=false`、`writer=false`，不接受原生形状表或猜测原生群置顶 schema。显式数据源诊断另提供 `GET /api/v1/independent/source/revision` 与 `GET /api/v1/independent/source/watch-targets`；它们只调用独立引擎既有的账号/source 选择和路径权限校验，响应固定带 `scope=alpha-independent-source-diagnostics`、`complete=false`、`native_schema_supported=false`，不扫描用户目录或修改数据。独立定时导出另提供 `/api/v1/independent/export-schedules`（GET 列表、POST `/api/v1/independent/export-attempts/:attempt_id/retry`；这些路径只包装本地 stateDir 的 CAS、bounded scheduler、运行/尝试记录和重试状态，响应固定带 `scope=alpha-independent-scheduled-export`、`complete=false`、`native_schema_supported=false`，不别名官方计划 API。`GET /api/v1/export-capabilities` 返回独立后端已验证的格式、媒体和时间范围能力；`GET /api/v1/export-stats?conversation_ids=a,b` 返回最多 100 个指定会话的消息总数、类别计数及首末时间。二者只描述独立 DTO，不冒充官方/native formatter 兼容。`GET /api/v1/sns/timeline`、`GET /api/v1/sns/usernames` 和 `GET /api/v1/sns/day-counts` 只读取显式 `moments.db`/`__alpha_moments_v1` synthetic fixture，响应标记 `synthetic_only=true`、`native_schema_supported=false` 并保留 `source_database`/`source_table`；日计数使用半开日期区间，最多 366 天，UTC 偏移限制为 -840 到 840 分钟；它们不读取或猜测真实微信 `SnsTimeLine`/`snsmessage`。朋友圈导出使用独立命名空间：`POST /api/v1/independent/moments/exports` 启动 metadata-only 任务，`GET /api/v1/independent/moments/exports/:job_id` 查询，`POST /api/v1/independent/moments/exports/:job_id/cancel` 取消。它们只消费 `moments.db`/`__alpha_moments_v1` synthetic fixture，响应带 `synthetic_only=true`、`native_schema_supported=false`，支持 `json`、`markdown`、`html`、`txt`；图片、视频和 live photo 请求明确返回 `HTTP_API_MOMENTS_MEDIA_UNAVAILABLE`。这些自有路径不实现或别名官方 `/api/v1/sns/export`，也不声称真实朋友圈媒体、点赞、评论或原生 formatter 语义。`GET /api/v1/favorites` 只读取显式 `favorite.db` 或 `favorites.db` 中的 `__alpha_favorites_v1` synthetic fixture，提供有界分页、类型/关键字/标签过滤和类型计数，并标记 `synthetic_only=true`、`native_schema_supported=false`；真实收藏库 schema、source lookup 和原生媒体 token `FAVORITES_MEDIA_UNAVAILABLE`。`GET /api/v1/records` 仅接受 `payments`、`friend_requests`、`revokes`、`calls`，支持不超过 512 字节、无控制字符和首尾空白的字面 `query`，以及 `ascending=true|false` 的分页，并在响应中保留 `GET /api/v1/independent/media/voice-playback` 只接受账号和 64 位小写十六进制 `media_id`，转发已验证的 `decodeVoicePlayback` 并返回 `wav_media_id`；响应标记 `synthetic_only=true`、`native_schema_supported=false`、`schema=__alpha_voice_playback_v1` 和 `scope=synthetic-voice-playback`。该路由不返回音频字节，不解析真实 VoiceInfo/SILK，也不接受原生媒体 token。`GET /api/v1/independent/media/voice-blob` 只读取调用方已选择的 `media_*.db` 中 `VoiceInfo.voice_data` 原始字节，响应以有界 Base64 返回并固定标记 `scope=alpha-independent-voice-blob-candidate`、`complete=false`、`third_party_candidate=true`、`decoded=false`、`native_schema_supported=false`；它不解码 SILK、不生成 `media1_` token，也不接原生 `transcribeVoice`。`GET /api/v1/independent/media/indexed/<sha256>` 只读取显式 `media-index.v1.json` 中与账号、会话、消息、媒体 ID、kind、rendition 和 SHA-256 全部绑定的文件；它返回经过 `readMediaEntry` 重新校验的字节，MCP 工具 `alpha-independent.media.read_indexed` 使用同一校验并返回有界 Base64。两者固定标记 `scope=alpha-independent-indexed-media`、`complete=false`、`native_schema_supported=false`，拒绝 `media1_`、任意路径、native cache、DAT/AES 和远程补齐。`POST /api/v1/analysis` 只接受已验证的聚合 scope 1–6 及其有界时间/会话参数；scope 5 统计正文显式 mention，scope 6 统计私聊足迹与同组 mention，报告固定标记独立 DTO 边界，`GET /api/v1/analysis/:analysis_id` 读取任务状态，`POST /api/v1/analysis/:analysis_id/cancel` 取消运行中的任务；报告限 64 MiB，完成时作为独立 JSON 返回。

`GET /api/v1/independent/source/schema` 与 MCP `alpha-independent.source.get_schema` 是维护诊断入口。它们只调用已选账号对应的独立引擎 `schema.inspect`，列出显式离线副本的数据库相对路径、表、列、SQLite 类型、NOT NULL 和主键序号。bridge 使用只读 SQLite 连接和固定上限（最多 128 个数据库、4096 张表、每表 256 列、响应 4 MiB），调用方不能传路径、SQL 或触发目录扫描；响应固定 `scope=alpha-independent-schema-diagnostics`、`read_only=true`、`complete=false`、`native_schema_supported=false`，不解释任何表名为 Alpha/native schema。

source token），不返回数据库密钥、原始 XML 或本地媒体路径。联系人 profile 只返回独立引擎能证明的存在性、共同群和群成员字段；通讯录目录只派生已验证的好友和群聊。工具参数对象和字段均做白名单校验，游标扫描最多 128 页/10,000 条；未知工具以 MCP `isError` 返回。没有发送消息、写入数据库、真实朋友圈 schema/互动/媒体下载、真实收藏库/原生收藏媒体语义或任意 SQL 工具；可选 ASR 只读取调用方明确提供的模型目录和 WAV media-index，仍不实现原生 VoiceInfo/SILK 转写。朋友圈和收藏 HTTP/MCP 工具只面向上述各自 synthetic fixture。公众号计划工具 `alpha-independent.official_plans.list/get/save/delete` 只保存账号隔离的本地 JSON 元数据；`list_attempts`、`request_attempt`、`get_attempt`、`archive_attempt` 只记录明确 blocked 的本地请求元数据。两组工具均标记 `local_metadata_only=true`，不联网、不抓取文章、不下载媒体、不执行计划。

新增的上下文工具只使用独立引擎已经验证的消息 DTO：`get_message_around` 接受消息 `id`、`serverId` 或 `localId`，`get_message_anchor` 支持首条消息和 `YYYY-MM-DD` 日期，`get_daily_message_counts` 使用独立引擎的会话日计数。它们不会返回原始 XML、本地媒体路径、数据库密钥或未经验证的原 Alpha 媒体 token。

`POST /api/v1/exports` 只允许独立引擎已验证的 `json`、`markdown`、`html`、`txt`、`xlsx`，以及由已验证消息 DTO 生成的派生 `chatlab-json`、`chatlab-jsonl`、`chatlab-v0-json`、`chatlab-v0-jsonl`、`sql`、`weclone` 格式；派生格式不声称与原 Alpha/native formatter 或第三方工具完全兼容。`POST /api/v1/media-metadata` 只允许 `media-json`、`media-csv`，可省略会话标识以导出账号范围，接收绝对 `destination_path` 和可选的毫秒时间范围；引擎会拒绝源目录/状态目录、符号链接、已有目标、媒体打包和未支持格式，不覆盖已有文件。该接口写入一个新导出文件，因此不把文件写入称作数据源只读操作。

这是一层独立适配器，尚未声称兼容官方文档中的全部 HTTP 路径和 MCP 工具。官方接口中依赖原生媒体、朋友圈、收藏、发送和完整 ChatLab 语义的路径仍需逐项取得 schema 和运行证据后实现。当前测试使用合成引擎 DTO，验证令牌、Host/Origin、HTTP 路由、游标/长整数转换、受控导出、MCP 工具、参数白名单和未知工具错误；没有读取真实微信目录。

新增的 `alpha-independent.mobile.get_message_media_bundle` 与 `GET /api/v1/independent/mobile/message-media-bundle` 只组合已验证消息 DTO 和声明性媒体引用，返回 metadata-only 索引状态，固定 `complete=false`、`native_schema_supported=false`、`media_ready=false`、`raw_available=false`、`official_alias=false`；不返回媒体字节、原始 XML、`media1_`、CDN URL 或 key。

新增的 `alpha-independent.mobile.get_session_bundle`、`alpha-independent.mobile.search_chat` 和 `alpha-independent.mobile.get_chat_context` 只组合已验证的账号、会话和消息 DTO，固定返回独立 scope、`complete=false`、`native_schema_supported=false`；`get_session_bundle` 只提供有界 `listAccounts`/`listConversations`/`listMessages` 结果，不包含未读数、静音、头像缓存、媒体 URL、原始 XML 或 native token。它们不实现或别名官方 mobile schema，也不加入 86/128 原生协议支持矩阵。

可用 `npm run audit:api` 重新生成覆盖报告（也可直接运行 `node scripts/audit-api-coverage.mjs --check`）。报告只统计官方路径和工具是否在独立适配器中有显式入口，不把合成 DTO、静态路由或协议声明当作真实 native 兼容证据；当前缺失项会作为审计结果保留，不能用空成功响应掩盖。

媒体元数据导出只写入消息 DTO 中已经验证的来源库/表/行号、时间、发送者、refs 和 display 字段，并固定写入 `metadataOnly=true`、`mediaReady=false`。它不读取、解密、下载、播放本地媒体，也不生成 Alpha 原生 `media1_` token。

公众号计划的 `/api/v1/independent/official-plans`（GET 列表、POST 创建/替换）和 `/api/v1/independent/official-plans/:schedule_id`（GET、DELETE）只操作账号隔离的本地计划元数据，并使用更新版本 CAS；它们不联网、不抓取文章、不下载媒体、不执行计划，也不映射 Alpha 的远程计划服务。对应 MCP 工具是 `alpha-independent.official_plans.list/get/save/delete`。`/api/v1/independent/official-plans/attempts` 及其单条查询、归档接口只记录本地执行请求的 blocked metadata。MCP 的 `alpha-independent.official_plans.list_attempts`、`request_attempt`、`get_attempt` 和 `archive_attempt` 使用同一账号隔离 JSON/CAS 存储；每条记录固定 `execution_supported=false`、`reason_code=INDEPENDENT_OFFICIAL_EXECUTION_UNAVAILABLE`、`complete=false`、`native_schema_supported=false` 和 `local_metadata_only=true`。这些接口不联网、不抓取文章、不下载媒体、不产生原生成功/运行状态，也不映射 Alpha 的 `OfficialScheduleRecord`。四个协议 schedule-record 分支另将同一 blocked-attempt 存储投影为本地等待输入、取消和归档状态，固定 `execution_supported=false`，不联网、不执行，也不把本地记录当作原生成功。
