# 年度分析接手记录

独立引擎现在实现了 `analyzeAnnual`（协议字段 104）的第一层只读统计。它只消费已经验证过的 `sessions.list` 和 `messages.list` DTO，按请求年份与 UTC 偏移统计总消息数、发送/接收数、活跃天数、活跃会话数、月分布、星期/小时热力图、消息类型媒体计数、前十会话和首条消息引用。

报告使用 Alpha 0.3.5 原有 `reportJson` 字段形状，算法版本和原生年报的完整语义仍未宣称兼容。当前明确为空或未实现的部分包括自然语言口头禅、回复速度、发起关系、夜聊伙伴、连续聊天、朋友圈互动、朋友圈统计和完整好友名称解析；这些字段不会从未知 payload 猜测。

年度扫描以 `sessions.list` 能发现的会话为范围，再分页读取每个会话的消息。若消息数据库中存在不在 `SessionTable` 的历史分库，会被桥接层的会话发现范围排除；`scannedMessages` 返回实际扫描量，`truncated` 只表示达到本次扫描上限，不能把它解释为完整覆盖证明。要补齐索引外历史表，需要取得授权的会话索引/数据库映射证据，或新增明确的只读会话枚举接口。

验证：`tests/engine-annual.test.mjs` 使用合成 v4 SQLite fixture，检查年份/时区校验、消息聚合、媒体计数、报告 JSON 和未覆盖会话的明确边界。未访问真实微信目录，也未写入聊天数据库。

聚合分析字段 110–112 复用同一 DTO 扫描边界，提供 bounded 内存任务、状态查询和取消。scope 3 要求本地时区完整年份并输出主进程可校验的 `alpha-annual-v2` 外壳；scope 1 只扫描私聊并输出 `alpha-aggregate-v1` 外壳；scope 5 统计群聊中消息正文里明确出现的 `@所有人`、`@all` 或账号自身用户名；scope 6 生成私聊会话足迹、回复延迟摘要以及同一组明确 mention。scope 5/6 的报告只基于已验证消息 DTO，固定标记 `complete=false`、`native_schema_supported=false`，不解析 XML `atuserlist`、昵称推断或原生分析表。任务最多保留 32 个、默认 TTL 10 分钟，进程重启不恢复；报告外壳中的空值只表示当前没有证据恢复对应算法语义。
